# Catalog Underwriter implementation plan

## Architecture

- Vinext/React application with server-compatible route handlers.
- Provider interfaces isolate MusicBrainz and future performance sources from the product model.
- A pure TypeScript financial core owns projection, DCF, scenarios, concentration, sensitivity, and diagnostics.
- A versioned stored artist snapshot keeps the demonstration reliable when public providers are unavailable.
- The underwriting route keeps the evidence, assumptions, valuation, and stress test in one stateful client workspace.

## Initial scope decision

The repository ships a complete, fixture-backed underwrite plus live public artist search and catalog metadata. The former Last.fm-based public cash-flow calibration is disabled; live automatic cash flow remains unavailable until defensible annual-consumption evidence and explicit rights economics exist. Hosting, the custom domain, persistent saved snapshots, accounts, and LLM memo generation remain separate follow-on work.
